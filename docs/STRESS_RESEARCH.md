## 2. Латентность ruaccent

Тестовая реплика: 70 слов, 579 символов (типичный ответ Sofia).

| Прогон | Время |
|--------|-------|
| 1 | 370ms |
| 2 | 426ms |
| 3 | 373ms |
| 4 | 433ms |
| 5 | 337ms |
| **Среднее** | **388ms** |

**Вердикт: 388ms — ПРЕВЫШАЕТ порог 200ms почти в 2 раза.** При текущем бюджете латентности (600-700ms total) добавление 388ms удваивает паузу и полностью ломает UX.

Загрузка модели: ~18 секунд (один раз при старте, допустимо).

## 4. Документация ElevenLabs

**Поиск:** docs.elevenlabs.io, help.elevenlabs.io — апрель 2026.

**Результат: U+0301 для русского НЕ документирован.**

Что найдено:
- **Phoneme tags** (`<phoneme alphabet="ipa">`) — работают ТОЛЬКО для английского, ТОЛЬКО на модели `eleven_flash_v2` (не v2.5, не multilingual). Источник: [Best practices](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices)
- **Alias tags** — замена слов альтернативным написанием. Работает для всех языков. Рекомендуемый подход для non-English.
- **Pronunciation dictionaries** — API фича, требует Scale план ($99/мес). Позволяет создавать alias-правила программно.
- Наш предыдущий research (09.04): "ElevenLabs **не поддерживает** stress marks для русского" (RESEARCH_REPORT_VOICE_AGENT_v1.md:225)

**Вывод: передача U+0301 в текст — недокументированное поведение. Если работает — случайно, может сломаться.**

## 5. Финальная рекомендация

### Вариант B: Ручной словарь замен (РЕКОМЕНДУЕТСЯ)

```python
STRESS_DICT = {
    "Белокуриха": "Белакуриха",    # фонетический хак, ударение на И
    "Белокурихе": "Белакурихе",
    "РИЗАЛТА": "Ризалта",          # lowercase = лучше парсится моделью
    "эскроу": "эскроу",            # уже нормально произносится
    "апарт-отель": "апарт отель",  # убрать дефис
    # ... добавлять по мере обнаружения
}
```

**Почему не Вариант A (ruaccent):**
- 388ms латентность — неприемлемо для голосового pipeline
- 75% точность — каждое 4-е слово потенциально хуже
- Бренды и топонимы (наши ключевые слова) — главная слабость
- ONNX баг требует патча, хрупкая зависимость
- U+0301 не документирован в ElevenLabs — ненадёжно

**Почему Вариант B:**
- 0ms латентность (dict lookup)
- 100% контроль над ключевыми словами
- Не зависит от внешних моделей
- Фонетические хаки ("Белакуриха" вместо "Белокуриха") — грязно, но ElevenLabs произнесёт правильно
- Легко расширять по мере обнаружения проблем в тестовых звонках

**Альтернатива для будущего:** если перейдём на Yandex SpeechKit TTS (99% ударений из коробки) + voice cloning когда появится — проблема уходит полностью. Но это отдельный трек.
