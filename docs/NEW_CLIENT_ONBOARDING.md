# Онбординг нового ЖК — пошаговая инструкция

> Как подключить новый жилой комплекс к Софии по образцу Атлантиса.
> Результат: клиент заполняет форму на сайте → попадает в Telegram → София квалифицирует
> с учётом специфики ЖК → лид уходит в раздачу менеджеру.
>
> Эталон: Атлантис (config key: `atlantis`, /start параметр: `ATL`).

---

## 1. Данные от клиента

Собрать у застройщика / отдела продаж:

### Обязательные
| Данные | Пример (Атлантис) | Зачем |
|--------|-------------------|-------|
| Название ЖК (полное + короткое) | Cosmos Crimea Atlantis / АК Атлантис | Для приветствия и карточки |
| Локация | Крым, Новофёдоровка | Контекст для диалога |
| Форматы и цены | Студия 16.8-19 млн, 1-спальня 20.7-22.7 млн... | Ответы на вопросы о ценах |
| Способы оплаты | ФЗ-214, эскроу, рассрочка, ипотека | Квалификация payment_type |
| Доходность (если инвестиция) | 5.2-17.6% годовых, ADR 15600-27636 ₽/ночь | Работа с инвестиционными клиентами |
| Особенности / УТП | Термальная скважина, собственный пляж, wellness | Уникальные аргументы в диалоге |
| Ссылка на презентацию (PDF) | https://api.atlantis-invest.ru/.../presentation.pdf | Отправляется в первом сообщении |

### Желательные
| Данные | Зачем |
|--------|-------|
| Инфраструктура (рестораны, SPA, спорт) | Ответы на вопросы об объекте |
| Сроки сдачи / стадия строительства | Возражения "а когда готово?" |
| Юридическая схема | Ответы на вопросы о безопасности сделки |
| Типичные возражения клиентов | Для RAG-примеров |
| Успешные диалоги менеджеров (5-10 шт) | Для RAG-примеров |
| FAQ от клиентов | Для RAG-примеров |

## 2. Промпт — надстройка над базовой Софией

София работает на двух уровнях:
- **Базовый промпт** — общие навыки продаж, квалификация, стадии диалога (одинаков для всех ЖК)
- **Надстройка** — объект-специфичные знания, инъектируемые через `source_object`

### 2.1. Карточка объекта (context file)

Создать файл `objects/<key>_context.md`. Структура по образцу Атлантиса:

```markdown
# <Полное название ЖК>

## Локация
<Город, район, особенности местоположения, климат>

## Концепция
<Что за проект, в чём уникальность>

## Масштаб
<Площадь, количество лотов, этажность, паркинг>

## Инфраструктура
<Пляж, рестораны, SPA, спорт, конференц-залы...>

## Форматы и цены (<дата актуальности>)
| Тип | Площадь | Цена от | Цена до |
|-----|---------|---------|---------|
| Студия | ... | ... | ... |
| 1-спальня | ... | ... | ... |
...

## Юридическое
<ФЗ-214, эскроу, способы оплаты>

## Инвестиционная модель (пример)
<Загрузка, ADR, чистый доход, доходность, рост цен>

## УТП
<3-5 ключевых преимуществ через + >

## Ссылка на презентацию
<URL>

## Инструкции для диалога
- <Как вести диалог именно по этому объекту>
- <Когда уместно предлагать альтернативы>
- <Что НЕ делать (не запрашивать контакты если уже есть, и т.д.)>
```

Этот файл загружается в `system prompt` генератора через `load_object_context()`.

### 2.2. prompt_addon

Короткая инструкция в `config/source_objects.py`, добавляется к системному промпту.
Типичные кейсы:

```python
# Контакт уже есть (форма Тильды):
"prompt_addon": "Контакт клиента уже получен через форму на сайте. НЕ запрашивай телефон, email или другие контактные данные. После квалификации сразу предлагай удобное время для созвона с экспертом."

# Контакта нет (прямой Telegram):
"prompt_addon": "Клиент пришёл напрямую. В конце квалификации запроси телефон для связи эксперта."
```

### 2.3. presentation_url

URL на PDF-презентацию. Отправляется клиенту в первом сообщении (greeting).
Хостинг — на стороне клиента или на нашем сервере.

## 3. База знаний (RAG)

RAG хранит примеры диалогов в ChromaDB (text-embedding-3-small, ~1965 примеров).
Датасет: `rag_training_data.json`.

### Что добавить для нового ЖК

#### 3.1. Примеры диалогов (5-10 штук)

Формат записи в `rag_training_data.json`:

```json
{
  "dialog_id": "crimea_spa_001",
  "outcome": "meeting",
  "client_type": "investor",
  "client_profile": "инвестор, бюджет 20 млн, ищет доходность",
  "exchanges": [
    {
      "stage": "GREETING",
      "user": "Здравствуйте, интересует КрымСпа",
      "assistant": "Добрый день! Рада, что заинтересовались КрымСпа!..."
    },
    {
      "stage": "QUALIFICATION",
      "user": "Хочу студию для сдачи в аренду",
      "assistant": "Отличный выбор! Студии от 12 млн, доходность..."
    }
  ],
  "stages_summary": {"GREETING": 1, "QUALIFICATION": 3, "PRESENTATION": 2, "MEETING": 1}
}
```

Стадии RAG: `GREETING`, `ACTUALIZATION`, `QUALIFICATION`, `PRESENTATION`, `OBJECTION`, `MEETING`, `CLOSING`.

#### 3.2. Типичные возражения

Добавить exchanges со стадией `OBJECTION`:
- "Дорого" → как аргументировать через доходность/рассрочку
- "Подумаю" → как мягко продвинуть к созвону
- "А есть дешевле?" → когда предлагать альтернативы
- Объект-специфичные: "А термалка реально работает?", "А Крым вообще безопасно?"

#### 3.3. FAQ

Добавить exchanges со стадией `PRESENTATION`:
- Вопросы о ценах, планировках, сроках
- Вопросы об инфраструктуре
- Вопросы о юридической схеме
- Вопросы о доходности

#### 3.4. Загрузка в ChromaDB

После обновления `rag_training_data.json`:

```bash
cd /opt/sofia-gpt-dev
python3 -c "from rag_module import _init_rag; _init_rag()"
```

ChromaDB пересоздаст коллекцию из обновлённого датасета.

## 4. Конфиг source_object

Файл: `config/source_objects.py`

### Добавить запись:

```python
SOURCE_OBJECTS = {
    "atlantis": { ... },  # существующий

    "crimea_spa": {
        "key": "crimea_spa",
        "name": "Крым SPA Resort",
        "short_name": "КрымСпа",
        "city": "Крым, Ялта",
        "keywords": ["крымспа", "crimea_spa", "crimspa", "#CRIMSPA"],
        "context_file": "objects/crimea_spa_context.md",
        "presentation_url": "https://example.com/crimea_spa_presentation.pdf",
        "greeting": "Рада, что заинтересовались КрымСпа! Вот презентация с планировками. Спрашивайте что угодно — а я задам пару вопросов, чтобы подобрать лучший вариант)",
        "prompt_addon": "Контакт клиента уже получен через форму на сайте. НЕ запрашивай телефон, email или другие контактные данные. После квалификации сразу предлагай удобное время для созвона с экспертом.",
    },
}
```

### Поля:

| Поле | Обязательное | Описание |
|------|-------------|----------|
| key | Да | Уникальный идентификатор, сохраняется в client_state.source_object |
| name | Да | Полное название для логов |
| short_name | Да | Короткое название для приветствия |
| city | Да | Город/район |
| keywords | Да | Триггеры для /start. Первый элемент — основной, #HASH — для /start параметра |
| context_file | Да | Путь к карточке объекта (относительно корня проекта) |
| presentation_url | Да | URL на PDF-презентацию |
| greeting | Да | Текст приветствия (без "Здравствуйте", оно добавляется автоматически) |
| prompt_addon | Да | Инструкция для LLM: запрашивать контакты или нет, особые правила |

## 5. Тильда / сайт

### 5.1. Форма захвата
- Стандартная форма Тильды: имя, телефон, email (опционально)
- Webhook Тильда → Битрикс24 (встроенная интеграция)
- SOURCE_ID в Битрикс должен быть **уникальным** для каждого сайта/ЖК

### 5.2. Redirect после формы
Вместо success page — redirect на Telegram бот:

```
https://t.me/humanAINeural_bot?start=CRIMSPA
```

Параметр после `?start=` должен совпадать с одним из `keywords` в source_objects (без #).

### 5.3. Критично
- Redirect должен вести на **PROD-бота** (`humanAINeural_bot`), НЕ на dev
- Если клиент не перейдёт в Telegram — лид будет в Битрикс, но без квалификации
- Параметр /start регистронезависимый

## 6. Битрикс

### 6.1. Что настроить на стороне Битрикс

| Что | Пример (Атлантис) | Описание |
|-----|-------------------|----------|
| SOURCE_ID | 397 | Уникальный источник для лидов с этого сайта. Создаётся в Битрикс: CRM → Настройки → Источники |
| Сотрудник-робот | ID 428 ("София AI") | ASSIGNED_BY_ID на время квалификации. Робот-распределитель не трогает лиды этого сотрудника |
| ID для запуска БП | 24932 | Сотрудник, на которого нужно переключить лид перед запуском БП. Уточнить у программиста Битрикс |
| TEMPLATE_ID БП | 152 | Бизнес-процесс проверки дублей и раздачи. Может быть общий или свой для каждого ЖК |
| Webhook URL | rest/426/uviwr0b350u3m6gf/ | Нужны права: **crm** (лиды) + **bizproc** (бизнес-процессы) |

### 6.2. Права webhook-токена

Минимум: `crm`, `bizproc`. Без `bizproc` — ошибка при запуске БП.
Проверить: Битрикс → Приложения → Вебхуки → права текущего токена.

### 6.3. Если другой Битрикс-аккаунт (другой клиент)

Нужен отдельный `BITRIX_BASE_URL` в .env. Сейчас один URL на все объекты.
При мультиклиенте: вынести BITRIX_BASE_URL в конфиг source_object или создать маппинг.

## 8. Тест-чеклист

### Подготовка
- [ ] Файл `objects/<key>_context.md` создан и заполнен
- [ ] Запись в `config/source_objects.py` добавлена
- [ ] RAG-примеры добавлены в `rag_training_data.json` и загружены в ChromaDB
- [ ] Форма на Тильде настроена: webhook → Битрикс, redirect → Telegram
- [ ] SOURCE_ID зарегистрирован в Битрикс
- [ ] Dev-сервисы перезапущены

### Функциональный тест (dev)
- [ ] `/start <PARAM>` в dev-боте → приветствие с названием ЖК и ссылкой на презентацию
- [ ] Диалог: вопрос о ценах → корректный ответ из карточки объекта
- [ ] Диалог: возражение → корректная обработка
- [ ] meeting_agreed → dialog_finished, finish_type="meeting"

### Интеграционный тест (prod)
- [ ] Заполнить форму на Тильде → лид создан в Битрикс с правильным SOURCE_ID
- [ ] Redirect → PROD-бот (humanAINeural_bot), НЕ dev
- [ ] `/start <PARAM>` → бот нашёл лид Тильды, привязал (лог: "Привязан к лиду Тильды #XXX")
- [ ] ASSIGNED_BY_ID сменился на 428 (София AI)
- [ ] Подождать 15 мин без ответа (или довести диалог до конца)
- [ ] Лог: "Финализация лида #XXX"
- [ ] Лог: "ASSIGNED_BY_ID → 24932"
- [ ] Лог: "BP 152 started for lead XXX"
- [ ] В Битрикс: статус лида изменился (БП отработал)
- [ ] Дубль-тест: заполнить форму с тем же телефоном → лид обновился, не создался новый

### Где смотреть логи
- **Telegram бот**: `/opt/sofia-gpt/sofia_bot.log` (НЕ journalctl!)
- **Bitrix операции**: `journalctl -u sofia-gpt.service` (logging модуль)
- **Web API**: `journalctl -u sofia-web-api.service`
