# База знаний Sofia-GPT

## Ключевые решения

### 12 января 2026: WAIT-логика только через Planner
**Проблема:** WAIT срабатывал на "35" (бюджет) потому что "записала" в тексте бота
**Решение:** Убрали проверку по тексту (should_skip_response), оставили только Planner
**Почему:** Planner проверяет реальный флаг state.meeting_agreed, а не угадывает по тексту

### 10 января 2026: Агентная архитектура
**Решение:** Extractor → State Manager → Planner → Generator
**Результат:** GOOD rate вырос с 64.8% до 93.75%
**Почему:** LLM не умеют считать и следовать жёстким правилам — это делает код

### 10 января 2026: Блок "НЕ ПОВТОРЯЙСЯ"
**Проблема:** Бот повторял вопросы 5-7 раз подряд
**Решение:** Жёсткий блок в промпте с детальными инструкциями
**Результат:** Повторы снизились с 6 жалоб до 0

## Известные проблемы и решения

### Проблема: WAIT на любые короткие сообщения
**Симптомы:** Бот молчит на "35", "Сочи", любой короткий ответ
**Причина:** should_skip_response проверял текст бота, а не state
**Решение:** Закомментировать блок (строки 465-470), использовать только Planner
**Файл:** bot_server.py

### Проблема: "записала" как маркер договорённости
**Симптомы:** WAIT после "Записала Алтай" (это не договорённость!)
**Решение:** Убрать "записала/записал" из MEETING_MARKERS
**Файл:** bot_server.py, строка 82

### Проблема: meeting_agreed на "да, могу"
**Симптомы:** Бот считал что клиент согласился на созвон
**Решение:** Уточнили правила в Extractor — только явное согласие на СОЗВОН
**Файл:** extractor.py

## Чего НЕ делать

- **Не проверять WAIT по тексту** — только через state.meeting_agreed
- **Не добавлять общие слова в MEETING_MARKERS** — "записала" вызывает ложные срабатывания
- **Не использовать gpt-5.2 с temperature** — не поддерживается
- **Не хранить методы класса в dict** — перезапишутся через setattr
